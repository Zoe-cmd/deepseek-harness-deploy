## 一、架构

```
                             公网                     回环（永不暴露）
┌──────────┐    :443      ┌─────────────┐  :3081   ┌─────────────┐  :3080   ┌──────────┐
│  浏览器   │ ───────────▶ │  Nginx      │ ───────▶ │ Auth Gateway │ ───────▶ │  Harness  │
└──────────┘   HTTPS TLS   │  TLS/HSTS   │          │  会话+限流+代理│          │ 仅回环    │
                           └─────────────┘          └─────────────┘          └──────────┘
      :80 HTTP → 301 跳 HTTPS                         登录页 /login 严格 CSP
```

- **Harness** 仅监听 `127.0.0.1:3080`，公网 `IP:3080` 直接拒绝连接（已验证）。
- **Auth Gateway** 独立零依赖 Node ESM 进程，仅监听回环 `127.0.0.1:3081`。
- **Nginx** 是唯一公网入口（:443 TLS / :80 跳转），代理到网关。
- 网关代理时重写 `Host: 127.0.0.1:3080` 并剥离 `Origin/Cookie/Authorization`，
  满足 Harness 浏览器信任围栏，全部 API（含管理/凭证/目录选择）可用，
  无需 `--trusted-host`；WebSocket（`/api/events.*`）与 SSE 均透传。

## 五、上线前注意事项

- 生产证书为自签名（`deploy/nginx/gen-cert.sh`）；正式上线请替换为真实 CA 证书，并启用 HSTS。
- 端口 80 的 301 重定向按域名 `dsh.example.com` 作用域，未影响服务器上既有站点。
- systemd 与 Docker Compose 均为可选方案，当前以原生进程 + 系统 nginx 运行。
